# BigDataSnowflake
Анализ больших данных - лабораторная работа №1 - нормализация данных в снежинку

Одна из задач data engineer при работе с данными BigData трансформировать исходную модель данных источника в аналитическую модель данных. Аналитическая модель данных позволяет исследовать данные и принимать на основе полученных данных решения. Классическими универсальными схемами для анализа данных являются "звезда" и "снежинка". В лабораторной работе вам предстоит потренироваться в трансформации исходных данных из источников в модель данных снежинка.

В ходе выполнения лабораторной работы я изучил процесс преобразования исходных данных, представленных в виде CSV-файлов, в аналитическую структуру. Основная задача заключалась в обработке набора данных, содержащего информацию о покупателях, продавцах, поставщиках, магазинах, товарах и операциях продаж, с последующим выделением фактов и измерений и их реализацией в базе данных PostgreSQL.

На первом этапе была проведена загрузка и предварительный анализ исходных данных. В работе использовалось 10 файлов формата CSV, каждый из которых содержал по 1000 записей, что в сумме составило 10000 строк. Для работы с базой данных использовалась PostgreSQL, развёрнутая с помощью Docker. В файле docker-compose.yml была настроена автоматическая инициализация базы данных, включая подключение CSV-файлов и выполнение SQL-скриптов при запуске контейнера. Это позволило автоматизировать процесс создания таблицы и загрузки исходных данных.

После загрузки данных был проведён их анализ с целью выделения логических сущностей. На основе этого были сформированы таблицы измерений: dim_customers, dim_sellers, dim_suppliers, dim_stores, dim_pet_categories, dim_products и dim_dates. Каждая из таблиц содержит атрибуты, относящиеся к конкретной сущности. Например, таблица покупателей включает персональные данные и информацию о питомцах, а таблица товаров содержит характеристики продукции, такие как название, категория, цена, бренд, описание и другие параметры. Отдельно была выделена таблица дат, предназначенная для хранения календарных характеристик, что упрощает выполнение аналитических запросов.

Далее была создана таблица фактов fact_sales, в которой хранятся ссылки на соответствующие измерения и основные показатели продаж, включая количество товара, цену за единицу и итоговую сумму. Такая структура обеспечивает удобство анализа данных по различным разрезам, например по покупателям, товарам, магазинам или времени.

На следующем этапе были разработаны SQL-скрипты для заполнения таблиц. Сначала выполнялось заполнение таблиц измерений, после чего на основе исходных данных формировалась таблица фактов с учётом связей между сущностями.

В процессе выполнения лабораторной работы я получил практическое понимание различий между исходной денормализованной таблицей и аналитической моделью данных. Также были закреплены навыки работы с SQL (DDL и DML), проектирования структуры базы данных и организации процесса загрузки данных с использованием Docker и PostgreSQL. В результате удалось преобразовать исходные CSV-данные в удобную для анализа структуру.

Что должно быть результатом работы?
1. Репозиторий, в котором есть исходные данные mock_data( * ).csv, где ( * ) номера файлов. Всего 10 файлов, каждый по 1000 строк.
2. Файл docker-compose.yml с установкой PostgreSQL и заполненными данными из файлов mock_data(*).csv.
3. Скрипты DDL (SQL) создания таблиц фактов и измерений в соответствии с моделью снежинка/звезда.
4. Скрипты DML (SQL) заполнения таблиц фактов и измерений из исходных данных.
